# 学习助手用户使用手册

本文档面向当前第一阶段的实际可用能力，按使用场景给出操作流程。

适用范围：

1. Feishu 私聊用户
2. CLI 本地用户
3. 需要跨渠道续接任务的高级用户
4. 负责初次绑定和运行期配置的管理员

---

## 一、先知道当前能做什么

当前稳定可用的能力包括：

1. 在 Feishu 和 CLI 之间识别为同一用户
2. 在高信任私聊场景下共享同一个 direct 会话
3. 生成学习计划、保存 scheduler 状态、触发主动提醒
4. 切换 `申论模式` 和 `行测训练模式`
5. 使用 `/new` 重置当前会话
6. 使用 `/help` 查看当前可用命令

当前公开可见的主要命令：

1. `/help`
2. `/new`
3. `/stop`
4. `/shenlun`
5. `/xingce`
6. `/mode status`
7. `/mode exit`
8. `/delegate-sync scheduler <目标>`
9. `/delegate-async scheduler <提醒内容>`

说明：

`/delegate-sync` 与 `/delegate-async` 是当前最稳定的 scheduler 调用方式，适合高级用户或管理员在 Feishu/CLI 中直接触发。

---

## 二、场景 1：第一次接入，绑定 Feishu 与 CLI 为同一用户

适用对象：管理员

操作流程：

1. 打开运行期身份配置文件 `workspace/identity/store.json`
2. 为同一个 `person_id` 增加多条 `bindings`
3. 确保 Feishu 用户 ID 与 CLI 用户名都绑定到同一个人
4. 打开 `workspace/routing/session_policy.json`
5. 确保 `trusted_direct.channels` 包含 `feishu` 与 `cli`

示例：

```json
{
  "people": [
    {
      "person_id": "owner",
      "primary_channel": "feishu",
      "trusted_channels": ["feishu", "cli"]
    }
  ],
  "bindings": [
    {
      "person_id": "owner",
      "channel": "feishu",
      "external_user_id": "ou_xxx"
    },
    {
      "person_id": "owner",
      "channel": "cli",
      "external_user_id": "your-local-username"
    }
  ]
}
```

完成判断：

1. Feishu 私聊与 CLI 都能解析到同一 `person_id`
2. 两边消息都落到 `person:<person_id>:direct`

## 三、场景 2：在 Feishu 和 CLI 之间续接同一个任务

适用对象：普通用户 / 高级用户

典型目标：

1. 在 Feishu 私聊开始任务
2. 回到本机 CLI 继续同一个任务
3. 保持同一上下文、同一学习模式、同一提醒状态

使用流程：

1. 先确认管理员已完成跨渠道绑定
2. 在 Feishu 私聊中开始对话或执行学习模式命令
3. 切换到 CLI，继续发送消息
4. 若两个渠道都属于 `trusted_direct`，系统会继续使用同一个 direct 会话

如何确认已经续接成功：

1. 两边上下文连续
2. 学习模式状态一致
3. scheduler 生成的计划和提醒仍是同一份状态

注意：

1. 群聊不会续接到这个 direct 会话
2. thread 会话也不会自动并到 direct 会话

---

## 四、场景 3：生成今天的学习计划

适用对象：高级用户 / 管理员

推荐流程：

1. 在 Feishu 私聊或 CLI 中发送：

```text
/delegate-sync scheduler 安排今天学习
```

2. 读取助手返回的计划文本
3. 后续提醒与复盘将基于同一 `person_id` 的 scheduler 状态继续运行

预期结果：

1. 返回“今日学习计划”文本
2. 计划会写入 `workspace/domain_agents/scheduler/state.json`
3. 后续 heartbeat 或主动提醒可基于这份状态工作

适合的使用时机：

1. 早晨准备当天学习安排
2. 切换学习重点后重新生成日计划
3. 需要从 CLI 恢复到 Feishu 继续执行时

---

## 五、场景 4：让助手稍后主动提醒你

适用对象：高级用户 / 管理员

推荐流程：

1. 在 Feishu 私聊或 CLI 中发送：

```text
/delegate-async scheduler 30 分钟后提醒我开始申论复盘
```

2. 先收到一条“任务已开始”的确认
3. 等待异步任务完成并由通知路由发到主直连渠道

预期结果：

1. 当前渠道先收到 job ack
2. 真正的主动提醒会按 `NotificationRouter` 决策发送
3. 默认优先送到主直连渠道，当前实现下通常是 Feishu 私聊

如何确认提醒发对了：

1. 提醒没有误发到群聊
2. 提醒目标是绑定到 `owner` 的 Feishu open_id
3. 同一用户从 CLI 发起的提醒也会回到主直连渠道

## 六、场景 5：进入申论模式或行测训练模式

适用对象：普通用户

### 1. 进入申论模式

操作：

```text
/shenlun
```

之后可以继续发送正常问题，例如：

```text
帮我列一个申论提纲
```

效果：

1. 当前 session 进入 `shenlun-mode`
2. prompt 只注入 `shenlun-mode` skill
3. 后续回答按申论训练语境组织

### 2. 进入行测训练模式

操作：

```text
/xingce
```

之后可以继续发送题目或拆解请求，例如：

```text
这道题怎么拆
```

效果：

1. 当前 session 进入 `xingce-drill`
2. prompt 只注入 `xingce-drill` skill
3. 不会继续携带申论模式 skill

### 3. 查看或退出当前模式

操作：

```text
/mode status
/mode exit
```

适合的使用时机：

1. 忘记自己当前在哪个模式
2. 要从专项训练切回普通问答
3. 准备开始一个新的普通任务

---

## 七、场景 6：重置当前会话，避免旧任务继续影响你

适用对象：所有用户

操作：

```text
/new
```

效果：

1. 清空当前 session 的短期上下文
2. 当前学习模式会被清掉
3. 后续对话从新会话开始

注意：

1. `/new` 重置的是“当前 session”
2. 它不会删除长期身份绑定
3. 它不会删除 scheduler 已经落盘的长期状态文件

---

## 八、场景 7：同一个人想在不同终端保持任务隔离

当前系统默认行为：

1. Feishu 私聊与 CLI 若都属于 `trusted_direct`，会共享 `person:<person_id>:direct`
2. 这适合跨端续接，不适合强隔离

如果你想隔离，有三种做法：

1. 使用不同 surface：例如一个在私聊，一个在群聊或 thread
2. 管理员把某个渠道移出 `trusted_direct.channels`
3. 使用 `/new` 重置当前会话，而不是继续复用旧上下文

当前不支持的能力：

1. 同一个 `person_id` 下手工切换多个命名 direct 会话
2. 例如 `/session switch work-a` 这类多工作区命令，目前没有内建实现

---

## 九、场景 8：群聊、私聊、线程应该怎么理解

规则如下：

1. 私聊：适合个人连续任务，可能进入 `person:<person_id>:direct`
2. 群聊：天然与私聊隔离
3. thread：若渠道提供 thread 元数据，则 thread 天然独立隔离

建议：

1. 个人任务、计划、提醒优先在 Feishu 私聊或 CLI 中完成
2. 群里更适合临时讨论，不适合放长期个人任务状态
3. thread 适合把某一话题或某一次练习单独隔离出来

## 十、常见问题

### 1. 怎么知道系统把我认成同一个人了？

看三件事：

1. 管理员配置里多个渠道是否绑定到同一个 `person_id`
2. Feishu 和 CLI 是否共享同一 direct 会话
3. 提醒是否统一回到主直连渠道

### 2. 为什么我在群里说过的话，CLI 里看不到？

因为群聊与私聊本来就是隔离的 session。

### 3. 为什么我切了模式，换个地方又没了？

学习模式是 session 级状态，不是 person 级长期状态。你切到别的 surface，可能进入的是另一个 session。

### 4. 为什么提醒回到了 Feishu，而不是 CLI？

因为当前主渠道和通知路由优先级指向 Feishu 主直连绑定。

---

## 十一、建议的日常使用方式

对当前第一阶段实现，推荐使用习惯如下：

1. 用 Feishu 私聊作为主入口
2. 用 CLI 作为高信任辅助入口，便于跨端续接任务
3. 每天先生成学习计划，再进入专项模式训练
4. 需要主动提醒时使用 scheduler async 能力
5. 任务太杂时用 `/new` 清理当前会话
6. 普通答疑和专项训练分开使用不同 session surface，避免上下文污染
