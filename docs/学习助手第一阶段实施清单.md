## 一、阶段目标

第一阶段不追求完整产品，只追求正确的骨架。

完成后应具备（当前已全部满足）：

1. 飞书 + CLI 双入口
2. 主 agent + 至少一个 domain agent
3. 基础身份统一
4. 基础会话策略
5. 基础调度与通知
6. 可通过技能系统切换学习模式

---

## 二、第一阶段不做什么

明确不做：

1. 眼动监控
2. 语音认知负荷分析
3. 可穿戴设备接入
4. 大规模多渠道全适配
5. 太多 domain agents
6. 完整学习画像系统

---

## 三、工作包拆分

### WP1：身份统一层

目标：

把当前 `channel:chat_id` 的粗粒度会话模型，升级为可扩展的 identity 模型。

建议新增：

1. `nanobot/identity/models.py`
2. `nanobot/identity/mapper.py`

建议能力：

1. `resolve_person(channel, user_id, metadata) -> person_id`
2. 渠道身份与 `person_id` 的映射存储
3. trusted / untrusted channel 标记

验收标准：

1. 飞书用户和 CLI 本地管理员可映射到同一 `person_id`

### WP2：会话策略层

目标：

把会话选择从“固定 `channel:chat_id`”升级为策略驱动。

建议新增：

1. `nanobot/routing/session_policy.py`

建议能力：

1. `resolve_session_key(person_id, channel, chat_id, metadata)`
2. 区分 DM / group / thread
3. 支持“飞书私聊 + CLI”共享直连会话的可选策略

验收标准：

1. 群聊和私聊不串上下文
2. 主渠道可维护稳定直连 session

### WP3：Primary Agent 编排层

目标：

在现有 `AgentLoop` 之上加一层编排逻辑，而不是立即重写全部主循环。

建议新增：

1. `nanobot/agent/primary.py`
2. `nanobot/agent/domain_registry.py`

建议能力：

1. 判断直接回答 or 委派
2. 调度 domain agent
3. 汇总结果后对外输出

验收标准：

1. 用户仍只看到一个统一助手人格

### WP4：Scheduler Agent

目标：

做第一个真正的 domain agent。

建议新增：

1. `nanobot/agent/domain/scheduler_agent.py`

建议能力：

1. 日计划生成
2. 番茄钟/倒计时
3. 学习提醒
4. 恢复协议建议

验收标准：

1. 能在飞书私聊中推送每日学习任务
2. 能定时提醒和复盘

### WP5：通知路由

目标：

让系统知道“该往哪个渠道发”。

建议新增：

1. `nanobot/notifications/router.py`

建议能力：

1. 回复回原渠道
2. 主动提醒发主渠道
3. 高风险确认发可信私聊渠道

验收标准：

1. 计划提醒不乱发到群
2. 默认走飞书私聊

### WP6：学习模式切换

目标：

在不大改核心架构的前提下，先让专项模式可用。

建议做法：

1. 通过技能系统定义模式
2. 通过 prompt 约束输出结构

第一批技能：

1. `shenlun-mode`
2. `xingce-drill`
3. `socratic-review`
4. `fatigue-recovery`

验收标准：

1. 用户能通过明确命令进入专项模式

## 四、代码改造建议

### 1. 优先修改的现有文件

1. `nanobot/cli/commands.py`
2. `nanobot/agent/loop.py`
3. `nanobot/session/manager.py`
4. `nanobot/agent/context.py`
5. `nanobot/channels/manager.py`

### 2. 暂时尽量不大改的文件

1. 各具体 channel 实现细节
2. provider 层
3. MCP 基础设施

原因：

1. 第一阶段先稳住编排和身份模型
2. 不要同时重构所有层

## 五、推荐实施顺序

### Step 1

实现 identity mapper 和 session policy

### Step 2

把 Feishu 设为主入口，CLI 作为高信任辅助入口

### Step 3

加入 primary agent orchestration

### Step 4

实现 scheduler agent

### Step 5

加入 notification router

### Step 6

通过技能系统实现第一批学习模式

---

## 六、第一阶段验收清单

做到以下几点，就可以进入第二阶段：

1. 飞书私聊可以稳定使用
2. CLI 能作为管理员调试入口
3. 至少一个用户的跨渠道身份映射可用
4. 群聊/私聊 session 不混乱
5. scheduler agent 能跑
6. 能主动推送学习提醒
7. 至少 2 个专项模式可以使用

---

## 七、第二阶段入口条件

只有当第一阶段稳定后，才进入第二阶段：

1. Knowledge agent
2. 公考专项 RAG
3. 苏格拉底式复盘体系
4. 倒计时硬中断训练
5. 更细的学习画像
