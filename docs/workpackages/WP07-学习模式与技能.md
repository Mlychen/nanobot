# WP07：学习模式与技能

## 一、工作目标

通过技能系统和 prompt 约束，实现第一批可用的学习模式。

第一阶段重点不是把专项能力系统化到底层，而是先让模式层能稳定切换、稳定使用。

---

## 二、边界与非目标

本包负责：

1. 模式定义
2. 模式进入/退出
3. 模式 prompt/skill 约束
4. 模式上下文注入

本包不负责：

1. identity/session/routing 基础协议
2. domain runtime
3. 复杂知识库和 RAG

---

## 三、前置条件

1. `WP03` 完成

可提前准备：

1. 模式说明文档
2. 技能草案

---

## 四、现有架构接点

当前可复用：

1. 技能系统
2. `ContextBuilder`
3. 主 agent 对最终输出的统一控制

---

## 五、新增内容

第一阶段建议落地：

1. `shenlun-mode`
2. `xingce-drill`
3. `socratic-review`
4. `fatigue-recovery`

必须具备：

1. 进入命令
2. 退出命令
3. 模式状态表达
4. 模式专属约束

---

## 六、实现流程

### Step 1：定义模式元信息

至少明确：

1. 模式名称
2. 触发命令
3. 目标行为
4. 不允许的行为

### Step 2：定义技能与 prompt 约束

要求：

1. 模式只改变行为和输出结构
2. 不改变身份与会话规则

### Step 3：接入主 agent

要求：

1. 主 agent 能识别当前是否进入模式
2. 主 agent 能把模式上下文注入当前回合

### Step 4：定义退出与重置

要求：

1. 用户可以显式退出
2. 模式之间不能隐式串用

---

## 七、关键细节与失败模式

### 1. 模式不能成为隐藏全局状态

要求：

1. 进入和退出必须可见
2. 当前模式应可查询

### 2. 模式之间不能互相污染

风险：

1. 申论模式的话术残留到行测模式
2. 复盘模式残留到普通问答

### 3. 模式层不能替代底层能力层

要求：

1. skills/prompt 只解决行为约束
2. 不负责身份、session、通知、调度

---

## 八、测试流程

### 1. 单元测试

覆盖：

1. 模式识别
2. 模式切换
3. 模式退出

### 2. 集成测试

覆盖：

1. 进入 `shenlun-mode`
2. 切换到 `socratic-review`
3. 退出回到普通模式
4. 模式下输出结构符合预期

### 3. 回归测试

确认：

1. 不启用模式时，主 agent 保持普通行为

---

## 九、验收标准

1. 至少两个模式可稳定进入和退出
2. 模式输出具有清晰差异
3. 模式不会污染非模式对话
4. 模式实现不要求重构底层 runtime

---

## 十、上游兼容注意事项

1. 该包优先通过技能和 prompt 层实现
2. 不应因为模式需求去改 provider 或 channel
3. 若需要修改底层 runtime，应先回到总览文档重新评估边界

## 十一、已落地实现备注（2026-03-06）

当前实现采用“会话级显式模式状态 + 内置技能注入”的第一版：

1. 新增 `nanobot/agent/modes.py`，提供 `LearningModeManager` 与模式元信息注册表
2. 第一版只交付两个模式：
   - `shenlun-mode`
   - `xingce-drill`
3. 显式命令支持：
   - `/shenlun`
   - `/xingce`
   - `/mode status`
   - `/mode exit`
4. 模式状态写入当前 session 的 `learning_mode` 元数据，只对当前 session 生效
5. `ContextBuilder` 现在会在当前回合注入激活模式对应的技能正文
6. `/new` 会显式清除模式状态，避免模式污染后续普通对话
